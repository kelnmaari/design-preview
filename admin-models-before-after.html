Case Study · The "dirty zone"

Before & After — tokenizing hardcoded components

7 files in web-svelte bypass the token system with hardcoded hex and phantom CSS variables (--card-bg, --color-blue) that don't exist — so they render fixed light colors and break in dark mode. Flip the theme above: the AFTER card adapts, the BEFORE card stays broken. That's the whole proof.

  • var(--card-bg, #ffffff) — token doesn't exist; falls back to #ffffff always.
  • #e0e0e0 / #f0f0f0 borders — invisible-on-dark, no contrast.
  • #1a1a1a / #666 text — black on near-black bg in dark mode.
  • #3b82f6 blue — wrong accent; doesn't match the indigo/rose system.
  • Status pills #dcfce7/#fef3c7/#fee2e2 — Tailwind-100 tints, blown-out on dark.
  • JS color map C = {gray, red, yellow...} — separate per file, mutually inconsistent.
